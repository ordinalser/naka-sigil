# Adversarial implementation audit

## Current revision — v0.12.5, 2026-10-17

- **Upgrading loses nothing.** Every published version (v0.9.5 to v0.11.1) and the 0.12.4 package were upgraded in a browser with their own saved data: user keys came through byte-identical. The upgrade step deletes only the retired keys, the last check's status and a public snapshot this version cannot read. It runs once per code version (`nakaBuild`), when the new worker first starts, rather than on `onInstalled`: after the files were replaced and Chrome restarted, Chromium 152 kept the previous worker, and the reload that then started the new one sent no install event. A retired key brings the step back (a downgrade and back). A failed step used to stall live checks silently for the worker's lifetime; it is now recorded like a failed check and retried by the next one.
- **Data this version cannot read is kept.** A write to Left rewrote the whole table from what `leftOf` could read, deleting other entries; it now keeps every entry and run it cannot read (`leftSave`). An unreadable holdings list used to clear every anchor at the next check; anchors are now removed only for pieces missing from a list that was read. Stored record rows that are not rows count as no records instead of breaking the holdings view. `isSnapshot` used pending rows before checking them and threw on a damaged one; it now checks them first, and a test damages every field of a real snapshot.
- **One failed write blocked the rest.** The worker's write queue stayed rejected after a job failed, so every later save in that worker failed; a failed job now rejects only its own request.
- **When Chrome keeps the previous worker.** Each page asks the worker which code version it runs (`shn-build`); an older worker leaves it unanswered. Then the popup and the extension page show one Finish the update card instead of numbers this version cannot read; its button stores which page asked (`nakaReopen`, read once, honoured for a minute, a known section only) and reloads, and the new worker opens that page again.
- **This week's sales.** The seen list (`nakaLeftSeen`) is rewritten whole with this week's sale keys, so it stays bounded; one piece sold twice is named once and the weekly line counts pieces; the line also shows when the last holding sold; closing it hands focus to the next line or Manage; the second click of a double click never opens a tile that moved up; View opens Left through a new `left` section, which the worker allows like the others.
- **The demo and the screenshots.** The portable demo no longer adds a listing picked from the data to its example holdings (a piece picked by rule could be anyone's); a test checks that every element the page script looks up exists in both templates, after a stale element broke the demo during this round. Real sales once quoted in the v0.12.4 notes were replaced by placeholders, and screenshot picks skip listings on a private list kept outside the repository.

## Revision — v0.12.3, 2026-10-17

- **Numbers pasted as a list.** A single-line field drops the line breaks of pasted text, so a list copied one number per line arrived joined ("2112\n2113" became 21122113), and fields capped at 400 characters cut a pasted "Copy all numbers" list after about 70 numbers. Fields that take several numbers now turn pasted line breaks into separators and hold 20,000 characters (every number); the enumeration comma "、" separates too.

## Revision — v0.12.2, 2026-10-17

- **A listing of ours that someone is buying.** It leaves us at the next block, but every plan treated it as ours: a free reclaim, a piece still earning afterwards, even a target. At block 971,827, assuming every minted piece of the affected traits were ours, Own a trait misjudged 34 of 50 traits (971,815: 6 of 9); on synthetic closing data plans reclaimed such a listing in 192 steps, took a piece being sold as a target 98 times and overstated our weekly change in all 125 plans that used one (by up to +241.24). Now a closing listing is removed as it closes, whoever's it is, costs nothing, and a piece of ours being sold counts as gone: no target, not ours in weekly totals, wanted back in Own a trait (marked "ours · selling"). One we are reclaiming is no step. Tests cover each.
- **Own a trait, independently recomputed.** Counts, lists, states, bonus once owned and cost: 20,802 checks on the bundled block 971,547 with live 971,815, and 20,824 with live 971,827, no difference; the new fields (stability, the floor range a smaller trait's bonus holds in, keep-listed, weekly totals): 35,137 and 35,311 rows on the same pairs, no difference; plans and joint plans with closing listings of ours: weekly figures exact. The zero-listing rule's supply equals the catalog count (minted and unminted) for all 351 traits at all three blocks. The keep-listed pick now also considers our listed pieces (kept or repriced to the line) and the highest weekly total; ties go to a piece already listed, then the lower number.
- **Within a block.** Caches no longer key on listings closing elsewhere: with a listing that shares no trait with our pieces starting to close, Raise weight ran no computation and changed nothing on screen (popup and page, measured); with one that does, it recomputed once and swapped the result in place, keeping unfolded rows, ticks and scroll.
- **The card reveal measured the card mid-animation.** The card's own scale pop made the overlay 92% or 106% of the card depending on timing, so the ring sat 8–12 px inside the artwork. The card is no longer transformed: the overlay now matches it exactly, and nothing is drawn over the artwork (pixel-identical to the bare card in every frame).
- **Look up as a sheet.** The views underneath are inert while it is open; Escape closes it unless a dialog is open or text is being composed; focus returns to the tile or the magnifier that opened it. Copying writes only plain numbers, only on a click.

## Revision — v0.12.1, 2026-10-17

- **Where links may lead.** The worker opens the extension page only at a known section, one of Raise weight's four tabs (`planner-buy|plan|lock|sim`), or one number's plan or simulator (`plan-N`, `sim-N`, at most five digits); anything else is refused (`bad-section`), as a test checks.
- **The popup's Raise weight.** It runs the page's own functions (`NakaPortfolio.rank`, `NakaPlanner.targetPlans`, `lockTraits`, `lockGroups`) on the data the popup already shows, only while that tab is open and after it has painted; work queued for an earlier block, holding list, added list or language is dropped, never shown.
- **Copy numbers.** Writes the wanted list to the clipboard only on a click; if the browser refuses, the button says so and nothing else happens. The list is numbers only, separated by commas, so pasting it back into a number field of this extension reads every number.
- **Each piece's own plan.** A row's plan, cost and weekly figures come from `plan()` and the same one-world `weeklyChange` as the combined plan; a test recomputes each row from `plan()` and checks the order (reachable first, free plans first, then value).

## Revision — v0.12.0, 2026-10-17

- **Listings closing between blocks.** A `/listings` read within a block is accepted only when `/pulse` before and after it shows the stored block and epoch and its active listings are exactly the snapshot's; otherwise the next block's rebuild carries the change. The record is kept apart from the snapshot and applied only to its own block, with rows that name active listings once each as a sale or a reclaim; malformed listings raise an error and the check backs off. Pages reuse one merged object while the record is unchanged, so caches are not rebuilt on every storage event.
- **Numbers added beside my holdings.** Written only after the saved list has been read, so a write never drops numbers saved from another tab; entries are resolved by the shared number lookup, deduplicated and capped at 3,333. The guard baseline of earlier versions is dropped on read.
- **The card reveal.** Only on this collection's page and only for `#naka-find=` with 1–5 digits; the hash is removed. The effect is an overlay of our own in page coordinates with `pointer-events: none`; the page's card only gains one class, so its links, hover and the page's own spinner keep working. Reduced motion turns the movement off. A card someone is already buying, by the page's spinner or by our closing record, is never celebrated.
- **Raise weight.** A joint plan of many pieces runs after the page has answered, and is cached by block, closing listings, holdings, added numbers and selection.

## Revision — v0.11.4, 2026-10-17

- **Whose run is it.** A holding is pending until the worker anchors it to the first block it reads after the holding was added, with the listing open then. Ownership is taken from that anchor through the public records: from the purchase or mint, through the owner's own reclaims, to a sale, an open listing or now. A listing that was open at the anchor and later sold is unclear (the user's sale, or a listing the user bought) unless the piece was added from the user's own Vault or Wallet page; the user answers once. Records out of chain order raise an error and leave the holding unknown instead of a guessed run. The selected snapshot's height is never used as the anchor (a fresh install would otherwise date every holding to the bundled 971,547).
- **One writer.** Every write of My holdings and its metadata goes through the worker's queue (`shn-holdings`, `shn-left`, the Wallet import and the per-block tick), so two tabs cannot lose each other's update. Keys are checked with `Object.hasOwn` and the inscription ID pattern, so `__proto__` and other non-ID keys are ignored.
- **Persisted data.** Sale history is accepted only for traits under 20 pieces, newest first, with any number of same-block ties (two windows, cheapest and dearest, give exact bounds); `closing` rows must name active listings, each once, as a sale or a reclaim; reward events reject future, foreign, duplicate and private-shaped rows. The official basis must also match K, v, `basePerBlock`, every `perBlock` and the six unminted pieces; an endpoint already at another block is treated as unavailable, not as a mismatch.
- **No repeated downloads.** A block already stored is never rebuilt; only a missing header time is read again. Finished-week tables are read one week at a time, validated, and never stored when invalid.
- **Tests that run the real thing.** Worker tests load the real worker in a VM whose storage behaves like Chrome's (values copied, every listener kept, `onChanged` dispatched asynchronously); the earlier harness kept one listener and never dispatched changes, so several ticks were never exercised. The worker's keep-alive timers are unreferenced in tests, so work left pending fails a test instead of hanging the run.
- **Market find.** `#naka-find=` accepts 1–5 digits and only on this collection's page. The number is typed into the page's own search box with the native value setter and an `input` event, the hash is removed, and the status note is text only. Nothing is stored or sent.
- **Release checks.** The privacy scan also rejects bech32 and base58 addresses, extended public keys, temporary and machine paths, the private workspace's names and the private extension ID. The ZIP is reproducible, so a reviewer can rebuild and compare the hash.

## Revision — v0.11.3, 2026-10-17 (superseded above where they differ)

Live snapshots carry public in-week exits with their listing blocks, so a holding bought or reclaimed after the week began no longer adds to this week's accrual; every eligibility sentence names the piece's own blocks and an inspection without that text is refused rather than shown generically. ## Calculation semantics

The most consequential risk is misunderstanding a correct formula. The popup, collection banner and each detail retain the synced height and provisional warning at every block, including blocks after reward launch. Activity adds a sale-time disclaimer. Every primary card value and detail uses total holding weight including the 100% base; only contribution rows use a signed bonus. Listed cards label their single-sale formula **After sale**; the shared block/quarter notice carries its provisional scope. Unknown-floor bounds remain theoretical. Listed/delisted reward eligibility is disclosed separately from the holding estimate.

## Popup number lookup

Lookup accepts a non-negative safe integer with an optional `#`, including zero, and rejects decimal/exponent/hex/HTML-like inputs. It searches the selected snapshot's stored number rather than relying on title text or item order. Results use the shared rule engine; source changes recalculate both height and value. Editing the input removes stale results. Missing entries are described as snapshot absence, not proof of nonexistence. Query text stays in popup memory and does not initiate network traffic. Browser tests cover Enter submission, exact/capped/ranged results, Chinese/English, missing/invalid input, exact inscription links, source changes and clearing.

## Residual limits

- Schema validation cannot authenticate a malicious but internally consistent API response. No consensus/proof verification or payout engine is implemented.
- The official quarterly measurement block and numbering convention remain unresolved; the rare-trait median is inferred from official data, not a published specification, as documented in RULES_AUDIT.md.
- A network request already sent cannot be unsent when live sync is disabled; the returned batch is discarded. A fully completed write before disable remains cached but is not the selected source while disabled.
- Browser/OS termination can interrupt a fixed-block load; the next worker detects the interrupted record. Existing good snapshots remain available.
- DOM fixtures exercise Vault placement without connecting a real wallet. Real market layout can change; reconciliation handles the inspected structures and removes out-of-scope annotations.
- Privacy scanning uses explicit file/field allowlists and known patterns. It is not a proof against arbitrary steganography or future edits.

## Block time and toolbar regression (0.7.1)

The former icon rasterizer silently dropped absolute SVG commands and relative subpath moves, and painted an opaque dark background. Its canonical-byte check reused that parser and could not detect incorrect artwork. The parser now handles the complete command subset used by the shared icon, restores subpath coordinates on close, and leaves unused pixels transparent. Independent decoded-PNG checks require visible amber/violet and transparent margins at all four sizes; browser rasterization supplies an independent SVG/PNG comparison.

Block freshness no longer uses `generatedAt` or check time. Optional public header metadata is bound to height/hash, missing timestamps remain unknown, and future timestamps have an explicit clock warning. Provider failure cannot prevent a valid weight sync. Header timestamps come from a public API; no proof-of-work, reorganization or chain-tip verification is implied.

## Single-sale simulation (0.8.0)

Individual public listing pairs must exactly reproduce every stored trait floor/count and collection floor/count. Duplicate, missing, malformed and inconsistent offers fail source validation. Legacy snapshots without offers remain valid and disclose that scenarios require a sync. Each model/cache belongs to one selected snapshot. Simulations remove only the selected ID, preserve tied floors, recompute all relevant aggregates and use the existing exact rule engine. Last trait listing, last collection listing, missing floors, number tiers, cap and unchanged input data are tested. All 197 current bundled listing scenarios are cross-checked against an independently reconstructed remaining-listing model.

The scenario is a conditional estimate at its own block, never a trade quote, payout or quarter forecast. Unknown-floor ranges are not confidence intervals. Holding weight changes are expressed in percentage points only for two exact results; ranges are shown as ranges without a guessed point change. Activity does not show purchase badges or panels.

## Display metric invariant (0.8.1)

Primary figures consistently show total holding weight including the 100% base. Grid/list, Activity, Vault, popup lookup, item details and before-sale formula references use the same weight formatter. A bonus is confined to the explicitly labeled calculation breakdown or rule tiers. The result and smaller reference share snapshot height, units and range semantics. Changed inputs retain inline before → after evidence; unchanged evidence is displayed once. DOM bounds use named total-weight attributes; old display-metric nodes are rebuilt. This avoids comparing +0% bonus with 100% total, and prevents source or layout changes from silently changing the meaning of a primary figure. No reward-eligibility or finalized-quarter claim was added.

## Listing state, official supplement and launch (0.9.2)

Missing offers never imply unlisted; status is selected-block status, including Activity. Listed zero rewards and holding formula are separate concepts. Supply20/19 boundaries, active-floor priority, last-sale thresholds, simulated sale price, missing sale data, same-block price ambiguity and future sales are tested. Optional sale arrays reject duplicates, invalid prices/indices and future heights. Live history failures do not inherit older sale records; floor synchronization remains usable. Trait counts are catalog counts, not historical mint proofs; the short official reply leaves exact rare-trait sale aggregation unspecified. No new-buyer waiting period, purchase deadline, quarterly finality, ownership or payout qualification is invented. Reward-start ETA stays anchored to the selected header and uses no wall-clock countdown.

## Primary controls and instant dismissal (0.9.3)

Query mode combines modes with language controls. Manual progress never replaces the live control's state label. Pointer exit dismisses inspection synchronously, even if the originating badge retains focus; there is no timer or fade. Keyboard focus/Enter/Space, touch, Escape and viewport/outside dismissal remain supported. ## Explicit hover origin (0.9.5)

A decorative stepped pointer and active-badge outline associate each inspection with its precise origin; rank tickets do not displace the normal weight target. Four-side placement uses visible viewport bounds and clipped ancestors. Frame corner clearance is independent of pointer-tip alignment, including partially visible badges. If the weight tile is entirely clipped but a ticket remains visible, the visible badge region is used; a fully clipped origin is dismissed.

The frame never covers its originating badge. When no adjacent side can fit the complete ledger, evidence scrolls inside a bounded surface while the source and primary total remain visible. A pointer hover bridge preserves inspection without adding a close delay. Resizing and SPA changes re-evaluate geometry; stale viewport notifications are ignored when their geometry already matches the positioned panel. The pointer is hidden from assistive technology. Calculation inputs, sale model, block basis and reward limits remain unchanged.

## Comparison selection and Compare refresh removal (0.10.3)

The separate Compare refresh path (button, background message and per-batch verification record) was removed; Compare follows the shared Live / Fixed block mode, so there is one data path to reason about. Adding a number on Compare previously toggled an already-selected NFT off; it now reports the existing selection. A full selection no longer disables add controls without explanation: market and popup controls state the limit and open Compare, and the Compare catalog explains it above the cards. Selection state is derived from one pure function (`compareState`) shared by every surface, and badge markers update in place without rebuilding inspections, so focus and pointer state survive.

The inspection used to sit 12px from its badge, so moving the pointer into it crossed empty space and closed it unless the path went through the stepped pointer. The bubble now shares an edge with the badge (rounded toward it, and above a selected badge's tab, which is part of the badge's hover area), replacing the pointer bridge; the decorative curved tail never intercepts the pointer.
